# Snap

**iOS 长截图工具** — 把一组连续拍摄的系统截图，自动拼接成一张长图。

</div>

## 这是什么

在任意 App 里（Safari、微信、外卖……）一边滚动一边连续截图，打开 Snap，
它会自动从相册里认出这组截图，算出它们之间的滚动量，拼成一张完整长图。

- 自动识别相册中成组的截图，不用手动一张张挑
- 自动去掉重复的导航栏 / 标签栏 / 输入框，成品里只保留一次
- 拼接预览 + 逐接缝手动微调（放大特写 + 1 像素级 ± 按钮）
- 水印（角标 / 平铺）与圆角外框
- 保存回相册（PNG 无损）

## 为什么不是「录屏 + 抽帧」

最初走的是这条路：用 ReplayKit 录屏，从视频帧里找重叠区域拼接。实测效果很差，
因为源头数据本身不可靠 —— 拿到的是**滚动过程中**的帧，带运动模糊，经过视频编码，
而且 App 无法知道用户什么时候在滑、什么时候停了。只能用 Vision 去「猜」两张模糊图的
相似度，遇到重复性列表就会认错行。

改用系统截图后，输入是无损的，信息质量高出一个量级。代价是要多按几次截图键
（可用「轻点背面」快捷键缓解）。

## 核心算法

管线全部在 [`Snap/Stitching/`](Snap/Stitching)，只依赖 CoreGraphics 和 Foundation，
因此可以脱离设备在 Mac 上直接测试。

| 文件 | 职责 |
| --- | --- |
| `FrameBitmap.swift` | 解成紧凑 BGRA，为每行同时算一个精确哈希和一个容差签名 |
| `OverlapMatcher.swift` | 求滚动量。按「最长连续匹配行」评分，再用像素相似度确认 |
| `StickyRegionDetector.swift` | 找出顶部/底部不滚动的冻结区 |
| `StitchPlan.swift` | 可编辑的拼接方案 |
| `StitchRenderer.swift` | 绘制成品，或只绘制某个接缝附近的窗口 |

两个关键设计：

**按「最长连续匹配行」评分，而不是匹配行总数。** 真正的滚动会产生一段贯穿整个重叠区的
不间断连续行；而均匀的导航栏跟自己错位重合，无论命中多少行，连续段都很短。
这一条同时挡掉了周期性列表「认错卡片」的问题。

**冻结区由滚动量反推。** 匹配到的连续段恰好就是滚动区，段外即是冻结区。这比
「所有帧在该行都一致」可靠得多 —— 后者会被状态栏时钟和轮播的搜索框文案打断。

### 一个被真实数据推翻的假设

最初假定「同一块内容在两张截图里逐字节完全相同」，于是用行哈希做精确匹配。
拿真实的信息流截图一测，这个假设直接崩了：

| 配对 | 滚动量 | 像素相似度 | 逐字节相同的行 |
| --- | --- | --- | --- |
| 0→1 | 1600 | 99.06% | 7% |
| 1→2 | 1652 | 99.61% | 52.9% |

内容明明对应，却几乎没有一行逐字节相同 —— 信息流里有直播缩略图、懒加载图片、
轮播文案，重叠区总有约 1% 的像素在变。所以匹配改成两段式：先用**容差行签名**
（每行 12 个列区间的平均亮度）找候选，再用真实像素相似度确认。

更完整的设计记录见 [`plan.md`](plan.md)。

## 构建

需要 Xcode（iOS 17+ SDK）和 [XcodeGen](https://github.com/yonaskolb/XcodeGen)。

```zsh
brew install xcodegen

git clone https://github.com/taoking/Snap.git
cd Snap

# 换成你自己的 Apple Developer Team ID；留空也能生成工程，
# 之后在 Xcode 的 Signing & Capabilities 里选也可以。
export SNAP_DEVELOPMENT_TEAM=XXXXXXXXXX
xcodegen generate

open Snap.xcodeproj
```

首次运行会请求相册权限，需要选「完全访问」，否则找不到可拼接的截图。

真机部署与打包的完整命令见 [`docs/install-on-iphone.md`](docs/install-on-iphone.md)。

## 测试

```zsh
./Tools/StitchTest/run.sh
```

在 Mac 上直接跑，不需要设备或模拟器。它合成一张长页面，按已知的滚动量切成若干张
「截图」（含会变化的时钟、冻结的导航栏和输入框），跑完整管线，然后逐行比对结果与
原始页面。最强的一条断言是：**拼接结果里的每一行都必须与来源的页面行逐字节相同**
—— 偏移量哪怕差一个像素都会失败。

覆盖场景包括：正常滚动、不均匀滚动、超过一屏的跳跃（应识别为内容缺口）、
高度重复的列表内容、重叠区内有动态内容、以及两张毫不相关的截图（应拒绝拼接）。

> 合成用例跑得快、断言强，但替代不了真实截图 —— 上面那个「逐字节相同」的假设
> 就是被真实数据推翻的。改动匹配逻辑后，务必再拿一组真实 App 的连续截图验证。

图标由 `Tools/MakeIcon` 生成，想改配色重跑即可。

## 已知限制

- 一次拼接的所有截图必须尺寸相同（同一设备、同一方向）。
- 成品高度上限 24000 px，超过会等比缩小。
- 滚动超过一屏会造成真实的内容缺口，只能提示，无法还原 —— 没截到的内容就是没截到。
  界面会标出缺口数量并提示「每滚动约半屏截一张」。
